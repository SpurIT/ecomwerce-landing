# ecomwerce.com

The landing page of Ecomwerce, a Shopify app that writes product pages: a static Astro site in `landing/`, and the brand files it is built from in `brand/`.

## How we work

- `master` is production: what is on `master` is what runs on ecomwerce.com.
- Every change goes in its own branch (for example `faq-copy` or `hero-motion`), then a pull request into `master`.
- Merging into `master` deploys automatically. The developer sets up the pipeline (see "Deploy").
- No direct pushes to `master`. Before a merge the build and the tests pass (`npm run build`, `npm test` in `landing/`); the full check (`npm run check`) runs before larger changes.
- This repository starts on 2026-11-12 from the design repository's `landing` branch: its commits that touch `landing/` and `brand/`, with their history. Design decisions and briefs stay in the design repository.

## What is here

- `landing/` - the site (Astro 7, no UI framework, no CMS). `landing/README.md` has the commands, the page variants and gates, consent and the ad tags, and where each part lives.
- `brand/` - the brand: `design-system/project/tokens.json` (colors, type, spacing), `design-system/project/components/bundle.css` (the components' classes), the logos in `brand/logo/`, the official Shopify App Store badges in `brand/shopify/`. The site reads these files from `../brand` at build time; never copy them into `landing/`.
- `bundle.css`, the component previews and the logo files are generated by `brand/tools/build-brand.mjs`: change the generator, run it, commit both.
- `package.json` (root) - Playwright, for the checks (`landing/scripts/check.mjs`) and the brand generator.

## Commands

```
npm install                       # root: Playwright for the checks and the brand generator
node brand/tools/build-brand.mjs  # root: regenerate bundle.css, the previews and the logo files

cd landing
npm ci
npm run build                     # landing/dist/, the static site
npm test                          # the edge logic's tests
npm run check                     # extra builds, screenshots, real clicks, the tags, Lighthouse (about 10 minutes)
npm run serve -- --country DE     # dist/ through the edge logic, as CloudFront serves it
```

Node 22.12 or newer.

## Deploy (to set up)

The plan made during the design work; nothing of it exists yet.

- Build: `cd landing && npm ci && npm run build` gives `landing/dist/`, a static site. Never deploy a build made with `EW_TAGS` or `EW_GATES_OPEN` set: those are for the checks only.
- Hosting: a private S3 bucket behind CloudFront (origin access control), an ACM certificate in us-east-1, DNS for ecomwerce.com (Route 53 recommended; the zone is at GoDaddy today: copy every record first, `app.ecomwerce.com` and mail included).
- Compression on: `compress = true` on every cache behaviour (Terraform's default is false). The performance budget, Lighthouse mobile LCP under 2.0 s, holds with gzip or brotli (1.80 s measured) and not without (2.10 s).
- A CloudFront Function on viewer-request from `landing/edge/geo.mjs`: visitors from the EEA, the UK, Switzerland and unknown countries get the opt-in copy under `/_optin/`, by the `cloudfront-viewer-country` header. `landing/edge/*.test.mjs` are its tests (`npm test`).
- Response headers from `landing/edge/headers.mjs`, plus Strict-Transport-Security at CloudFront. The page's own Content-Security-Policy is a meta tag built from the tag ids in use (`landing/src/lib/site.mjs`).
- Caching: html short-cached (it changes with every deploy), the hashed files under `/_astro/` immutable, an invalidation after each deploy.
- CI: GitHub Actions on a push to `master`: build, `npm test`, sync `dist/` to S3, invalidate. AWS access through a GitHub OIDC role, no keys in the repository. Optional: `npm run check` on pull requests (Playwright and Lighthouse; about 10 minutes).
- Before launch the site still needs its inputs, all in `landing/src/data/landing.mjs` and `landing/src/config/tags.mjs`: the App Store listing url, the support email, the legal texts, the ad tag ids.
